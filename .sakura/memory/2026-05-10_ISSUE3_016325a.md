### 6. 经验教训

值得在未来 Issue 分析中固化下来的要点：

1. **403 错误的标准诊断清单**：
   - 优先检查 User-Agent、Referer、Origin
   - 确认目标 API 是否变更了访问策略（如新增令牌、IP 白名单、签名）
   - 检查同一域名下其他方法是否有同类头缺失

2. **反爬问题需做“全量域检查”**：
   - 当修复一个 API 的请求头时，必须扫描整个仓库中调用相同域名的所有方法。

3. **建议沉淀为项目记忆规则**：
   - **rule-403-check-all-endpoints**：修复 403 后，必须验证同域名下至少 80% 的 API 方法。
   - **rule-no-hardcoded-browser-version**：User-Agent 中不出现具体版本号，保留 `Chrome/` 或使用 `python-requests` 默认 UA + 可配置补充头。

4. **需求设计预警**：
   - 外部 API 依赖的插件应内置“UA 时效性提醒”或允许用户自定义 headers。
   - 未来如果再次出现同类 403，应直接升级为架构改进（统一请求层），而不是继续逐个方法打补丁。
