### 6. 经验教训

#### 值得在后续 Issue 分析中关注的要点

| 教训 | 具体说明 |
|------|----------|
| **影响面扫描** | 发现一个 API 报错时，必须主动查询该域名下所有调用点，并在分析中列出 |
| **重复检测需证据** | 不能只说“可能是重复”，需引用原 Issue 标题或关键日志片段 |
| **风险前置提示** | 即使修复方案简单，也要列出“若仍失败”的潜在原因（IP 风控、Cookie 等） |
| **标签适度** | 避免使用低置信度的 `help wanted`，若不确定可省略或标注“可选” |
